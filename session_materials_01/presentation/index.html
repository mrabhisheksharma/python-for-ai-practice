Python Core Basics

Before moving into complex structures, we need to understand how Python stores and evaluates basic information. This is optional if you already know basic programming.

1. Variables & Data Types

Python doesn't need you to declare a type upfront — the variable's type is decided by what you assign it.

name = "Model-A"        # str
accuracy = 91.4         # float
epochs = 50             # int
is_trained = True       # bool

print(type(accuracy))
accuracy_str = str(accuracy)

2. Operators

Basic math, comparisons, and logic to evaluate state.

total = 10 + 5
avg = total / 2

# Initialize variables
accuracy = 91.4
is_trained = True
epochs = 50

# Comparison & Logical
print(accuracy > 90)
print(is_trained and accuracy > 90)

# Assignment shorthand
epochs += 10

Control Structures

How we control the flow of execution: making decisions and repeating actions.

1. if / elif / else

Standard branching — condition checked, one true path taken.

if accuracy >= 90:
    print("Excellent model")
elif accuracy >= 75:
    print("Good, needs tuning")
else:
    print("Needs more work")

2. for loops

"Loop over a collection" is the pattern you'll use constantly once looping over API results.

scores = [91.4, 85.2, 78.0]
for score in scores:
    print(score)

# Using len()
print(f"Total scores: {len(scores)}")
for i in range(len(scores)):
    print(f"Index {i}: {scores[i]}")

# Reverse loop
for score in reversed(scores):
    print(score)

3. while loops

Keep going until a condition is false.

epochs_left = 3
while epochs_left > 0:
    print(f"{epochs_left} epochs left")
    epochs_left -= 1

Data Structures in Python

Python's built-in data structures are how you hold data before you wrap it in a class. Dictionaries specifically mirror every API response and JSON payload you'll work with.

1. Lists

Ordered, mutable, allows duplicates. The default "collection of things" — datasets, batches, results almost always start as a list.

scores = [91.4, 85.2, 78.0]
scores.append(88.9)
print(scores[0])        # indexing
print(scores[-1])       # last item
print(scores[1:3])      # slicing
91.4
88.9
[85.2, 78.0]

2. Tuples

Ordered, immutable — once created, can't be changed. Use when the data shouldn't change after creation.

coordinates = (28.7, 77.1)
name, accuracy = ("Model-A", 91.4)   # unpacking
print(name)
print(accuracy)
Model-A
91.4

3. Dictionaries

Key-value pairs — the shape of virtually every API request and response you'll work with.

model_info = {
    "name": "Model-A",
    "accuracy": 91.4,
    "tags": ["nlp", "v2"]
}
print(model_info["name"])
model_info["accuracy"] = 92.0     # update
for key, value in model_info.items():
    print(key, value)
Model-A
name Model-A
accuracy 92.0
tags ['nlp', 'v2']

4. Sets

An unordered collection of unique elements, often used to eliminate duplicate values and perform mathematical set operations.

tags_a = {"nlp", "v2", "prod"}
tags_b = {"nlp", "vision"}
print(tags_a & tags_b)   # intersection
print(tags_a | tags_b)   # union
{'nlp'}
{'nlp', 'v2', 'prod', 'vision'}

Functions & Modules

Packaging code into reusable blocks and importing external libraries.

1. Functions

Define logic once, use it anywhere. Functions keep code DRY (Don't Repeat Yourself).

def calculate_accuracy(correct, total):
    if total == 0:
        return 0.0
    return (correct / total) * 100

print(f"Accuracy: {calculate_accuracy(85, 100)}%")
Accuracy: 85.0%

2. Modules & Packages

Python's superpower is its ecosystem. Use import to bring in external code.

import math
import random

print(f"Pi: {math.pi}")
print(f"Random value: {random.uniform(-1, 1)}")
Pi: 3.141592653589793
Random value: 0.4218... (varies between -1 and 1)

3. Lambda Functions

Throwaway, unnamed functions. Often used with sort().

models = [{"name": "A", "accuracy": 91.4}, {"name": "B", "accuracy": 85.2}]
models.sort(key=lambda m: m["accuracy"], reverse=True)
for m in models: print(f"{m['name']}: {m['accuracy']}")
A: 91.4
B: 85.2

Object-Oriented Programming (OOP)

Let's look at generic, framework-relevant examples. These patterns are everywhere in AI SDKs.

1. Classes & Objects

A class is a blueprint; an object is an instance holding its own state.

class AIModel:
    def __init__(self, name, accuracy):
        self.name = name
        self.accuracy = accuracy

    def summary(self):
        return f"{self.name}: {self.accuracy}% accuracy"

model = AIModel("Model-A", 91.4)
print(model.summary())
Model-A: 91.4% accuracy

2. Abstraction

Expose what something does, hide how. An Abstract Base Class (ABC) defines a contract.

from abc import ABC, abstractmethod

class BaseModel(ABC):
    @abstractmethod
    def predict(self, data):
        pass

class TextModel(BaseModel):
    def predict(self, data):
        return "positive" if "good" in data.lower() else "negative"

model = TextModel()
print(model.predict("This is a good day!"))
# model = BaseModel() # TypeError: Can't instantiate abstract class BaseModel
positive
# Direct instantiation: BaseModel() raises TypeError: Can't instantiate abstract class BaseModel

3. Inheritance & Polymorphism

Inheritance: A subclass reuses and extends a parent's behavior.

Polymorphism: Different classes respond to the same method call in their own way. 

class AdvancedModel(AIModel):
    def __init__(self, name, accuracy, version):
        super().__init__(name, accuracy)
        self.version = version

    def summary(self):
        base = super().summary()
        return f"{base} | version: {self.version}"

# Polymorphism in action
models = [AIModel("Baseline", 70.0), AdvancedModel("Advanced", 91.4, "v2")]
for m in models:
    print(m.summary())
Baseline: 70.0% accuracy
Advanced: 91.4% accuracy | version: v2

4. Encapsulation

Hide internal state and require all interactions to be performed through an object's methods.

class APIClient:
    def __init__(self, api_key):
        self.__api_key = api_key  # private attribute

    def fetch_data(self):
        # Uses the hidden key internally
        return f"Fetching data using hidden key: {self.__api_key[:4]}..."

client = APIClient("sk-12345XYZ")
print(client.fetch_data())
# print(client.__api_key) # AttributeError: 'APIClient' object has no attribute '__api_key'
Fetching data using hidden key: sk-1...
# Direct access attempt: print(client.__api_key)
AttributeError: 'APIClient' object has no attribute '__api_key'

Exception Handling

In AI applications, APIs fail frequently. Defensive programming via exception handling is your safety net.

1. try/except Basics

try:
    result = 10 / 0
except ZeroDivisionError as e:
    print(f"Something went wrong: {e}")
finally:
    print("This always runs — cleanup goes here.")

2. Custom Exceptions

class ModelNotTrainedError(Exception):
    """Raised when prediction is attempted before training."""
    pass

class SimpleModel:
    def __init__(self):
        self.trained = False

    def predict(self, x):
        if not self.trained:
            raise ModelNotTrainedError("Call .train() before .predict()")
        return x * 2

m = SimpleModel()
try:
    m.predict(5)
except ModelNotTrainedError as e:
    print(f"Custom error caught: {e}")
Custom error caught: Call .train() before .predict()

File Handling

Reading from and writing to the local filesystem using Context Managers.

1. Reading & Writing Safely

The with statement ensures the file is automatically closed, even if errors occur.

# Writing
with open("data.txt", "w") as file:
    file.write("User: Hello\n")

# Reading
try:
    with open("data.txt", "r") as file:
        print(file.read())
except FileNotFoundError:
    print("File not found.")

2. JSON Files

Working with structured JSON data using json.dump and json.load.

import json

result = {"model": "gpt-4o-mini", "accuracy": 91.4, "tags": ["nlp", "v2"]}

# Writing JSON
with open("result.json", "w") as f:
    json.dump(result, f, indent=2)

# Reading JSON
with open("result.json", "r") as f:
    loaded = json.load(f)

print(loaded["model"])

Multithreading vs Multiprocessing

Doing multiple things at once to speed up execution.

1. Multithreading

Best for I/O Bound tasks like network API calls, reading files, or downloading data. Threads are like multiple workers in the same kitchen—they share the exact same memory space (ingredients) and can easily pass data between each other, but they must coordinate to avoid stepping on each other's toes.

import threading
import time

def api_call():
    time.sleep(1) # Simulating network wait

threads = [threading.Thread(target=api_call) for _ in range(3)]
for t in threads: t.start()
for t in threads: t.join()

2. Multiprocessing

Best for CPU Bound tasks like heavy math, data crunching, or model training. A Process is like spinning up an entirely separate kitchen with its own independent chef and ingredients. They don't share memory, allowing them to run truly in parallel across multiple CPU cores without conflicts.

import multiprocessing

def heavy_math(num):
    return sum(i*i for i in range(num))

if __name__ == "__main__":
    processes = [multiprocessing.Process(target=heavy_math, args=(1000000,)) for _ in range(2)]
    for p in processes: p.start()
    for p in processes: p.join()

Calling API

Loading the API key from a .env file & calling an LLM.

1. Basic API Call

from dotenv import load_dotenv
import os
from openai import OpenAI

load_dotenv()
client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))

try:
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": "What are the top 3 new developments in AI this month?"}]
    )
    print(response.choices[0].message.content)
except Exception as e:
    print(f"API call failed: {e}")

2. File-based Refactor

Read the prompt from prompt.txt and write the LLM response to response.txt.

from dotenv import load_dotenv
import os
from openai import OpenAI

load_dotenv()
client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))

with open("prompt.txt", "r") as f:
    prompt = f.read().strip()

try:
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": prompt}]
    )
    reply = response.choices[0].message.content

    with open("response.txt", "w") as f:
        f.write(reply)

    print("Response saved to response.txt")
except Exception as e:
    print(f"API call failed: {e}")

📝 Practice Activity — "Personal Task Prioritizer"

Solidify everything you've learned into a single, cohesive build.

Core Steps

  1. Create a class Task with attributes name, priority (1–5), and deadline_days.
  2. Add a custom exception InvalidPriorityError, raised inside __init__ if priority isn't between 1 and 5. Create 5–6 tasks including at least one invalid one, and handle the error with try/except when creating them.
  3. Store the valid tasks in a list. Loop through and print each one in a readable line, e.g. "Finish report — priority 4, due in 2 days".
  4. Save that list (converted to dicts) to a JSON file, tasks.json.
  5. Read tasks.json back and print all the tasks from the loaded data, to confirm the save/load worked.

Optional Advanced Part

Pick either or both:

  • Use a list comprehension to pull out "urgent" tasks (deadline_days <= 3), and sorted() with a lambda key to rank all tasks by priority.
  • Using the file-based API demo pattern: build a prompt from the task list (e.g. "Given these tasks, suggest what to tackle first and why"), send it via the API call, and append the AI's response to tasks.json instead of overwriting the file.
